# ai-newsdesk V1 design

Date: 2026-10-14. Status: approved; judge decision updated after the step 0 bake-off (ADR-0001).

## 1. Purpose

The owner is tired of the noise on X. ai-newsdesk is a personal, high-signal AI news feed. It collects news from AI labs and from a curated list of respected people, throws away the junk, merges duplicates into single stories, summarises them with the cheapest Claude model, and presents them in a beautiful web UI with a daily briefing.

Single user, lab network only, behind the shared Caddy at `ai-newsdesk.toolbox.home.arpa`.

### Success criteria

- The Today page shows the day's AI stories, each with a summary, a "why it matters" line, a signal score and links to every source that covered it.
- Reposts and echo accounts on X never appear; only people on the owner's list do.
- A readable briefing is ready each morning.
- Claude API spend never exceeds the monthly cap (default $5).
- No paid X access, ever.

### Out of scope for V1

- Agent-written deep-dive articles: on-demand explainers researched through research-engine. These are V2. V1 keeps its data model ready for them (stories with their sources), but builds nothing for them.
- Email digests, multiple users, MCP/API for agents, embeddings or vector search.

## 2. Architecture

- **One container:** a Python 3.12 FastAPI app built with uv, ruff, pyright and pytest, matching research-engine's tooling.
- **Storage:** SQLite (WAL mode) on the named volume `app-data`, mounted at `/data`.
- **Scheduler:** an in-process asyncio scheduler. The collection schedule and the daily briefing time come from settings stored in the database, so a change takes effect without a restart.
- **UI:** server-rendered Jinja2 templates, htmx for small interactions (thumbs, filters, source edits), and hand-written CSS. There is no front-end build chain.
- **research-engine:** called directly at `http://research-engine-app:8000` over the external `proxy` network, which the app joins anyway as the web-facing service. It authenticates with the `X-API-Key` header. The key is `RESEARCH_ENGINE_API_KEY` in our `.env`, a copy of research-engine's key that the owner provides or that I copy without printing it.
- **AI: Claude Haiku 5.5** (the official `anthropic` SDK) does both **judging** (suitability review, same-story check) and **writing** (summary, why-it-matters, the daily briefing). This was decided by the step 0 bake-off (section 12, ADR-0001): on 623 hand-labelled items, Haiku caught more junk and hid fewer good items than TypeSafe Jev. Jev stays a supported alternative behind the `Judge` protocol (`judge_provider` setting), but isn't the default and isn't required.
- **Boundaries:** every external dependency sits behind a protocol: `Source`, `ResearchEngine`, `Judge`, `Writer`, `Clock`. Only `app.py` wires up the concrete classes. Tests use fakes.

### Units

| Unit | Responsibility |
|---|---|
| `sources/` | One adapter per source kind; each returns `list[Candidate]` and never raises for one source's failure |
| `research_engine.py` | Thin async client for `/v1/search` and `/v1/fetch`, with Envelope parsing and error mapping |
| `normalise.py` | Tidies URLs (strips tracking parameters, standardises the host) and builds a stable item ID |
| `dedupe.py` | Exact-URL and near-duplicate-title matching against recent items |

| `write.py` | Haiku summary and why-it-matters for stories that passed review |
| `cluster.py` | Shortlists candidate stories in code; the judge's same-story check decides |
| `briefing.py` | Writes the daily briefing from the top stories |
| `budget.py` | Spend ledger, price table, monthly cap and daily review cap |
| `feedback.py` | Thumbs up/down: source weights and preference examples |
| `scheduler.py` | Runs the pipeline on the configured schedule |
| `store.py` | SQLite schema and queries |
| `web/` | Routes, templates, static CSS, auth |

## 3. Sources

The seed list lives in `config/sources.yaml`. It's loaded into the database on first run, then edited in the UI. Every source has a **trust level**: `primary` (a lab's own channel), `trusted` (a respected individual) or `discovery` (aggregators and searches).

| Kind | How | Seed examples |
|---|---|---|
| `feed` | Direct RSS/Atom fetch with httpx (ETag/Last-Modified honoured) | Anthropic, OpenAI, Google DeepMind, Meta AI, Mistral, Hugging Face blogs; Simon Willison, Lilian Weng, Interconnects, Import AI, Latent Space, Karpathy's blog |
| `x_person` | research-engine search `site:x.com/<handle>`, `time_range` matched to the interval since the last run; only results whose URL handle equals the source handle are kept | A starting set of respected researchers and lab leads, edited by the owner |
| `search` | research-engine topic searches (`intent` news where available) | "new AI model release", "AI research paper", "AI lab announcement" |
| `arxiv` | arXiv API, categories cs.AI, cs.CL and cs.LG; pre-filtered hard (authors or affiliations linked to trusted sources, plus HN/X mentions) | — |
| `github` | Releases Atom feed per repo | Key open-model and tooling repos |
| `hn` | HN Algolia API, AI-related stories above a points threshold (default 100) | — |

Findings that shaped this (probe on 2026-10-14): research-engine search returns recent X post URLs with author handles and snippets of about 200 characters. Fetching X pages is blocked by X's robots.txt, which research-engine respects. So X items are snippet-only and link to the original. This is the accepted trade-off for zero X cost.

**Full text:** for `feed`, `search` and `hn` items that survive the pre-filter, the article body is read through research-engine `/v1/fetch` (Markdown), capped at about 1,500 tokens before it's sent to the LLM. If the fetch fails, the feed summary or snippet is used instead.

## 4. Pipeline

One **run**, triggered by the schedule or by "Refresh now" on the Settings page:

1. **Collect:** all enabled sources run concurrently, each with its own timeout. Each source's result (count, error, duration) is recorded.
2. **Normalise and dedupe:** items already seen are dropped. A near-duplicate title within 72 hours is linked to the existing item's story.
3. **Pre-filter (free):** heuristic score = trust-level weight × the source's feedback weight + signals (HN points, appearance in more than one source, keyword boosts) − blocklist penalties. Items below the drop threshold are kept in the database as `dropped`, so they can be audited, but never shown.
4. **Review (Haiku, `HaikuJudge`):** survivors are sorted by heuristic score, and the top N are reviewed, where N is limited by the remaining daily review cap and the monthly budget. Items are reviewed about 10 per request, with structured output (`messages.parse`), effort `low`, and a fixed, cached system prompt. That prompt describes the owner's bar for high-signal AI news and treats each item as untrusted data inside `<item>` tags. Each item's input is `source` (name, kind, trust level), `title`, `author` and `text` (the article excerpt). The bake-off showed that the full excerpt matters a lot: headline-only judging is much worse. Per item, the output is `signal` (0–10), `junk` (bool), `category` (`model_release`, `research`, `product`, `policy`, `industry`, `opinion`, `other`), and `same_story_id` (nullable; see step 5). Stored signal = `0 if junk else signal`, multiplied by the source's feedback weight. The show threshold defaults to **4**, which was the best operating point in the bake-off; it can be changed in settings. Items left over wait for the next run, oldest first, and expire after 48 hours.
5. **Cluster:** for each item at or above the show threshold, code shortlists up to 5 open stories from the last 72 hours by title and entity word overlap. Their headlines go into that item's review request as candidates, and the judge returns the matching `same_story_id`, or null for a new story. The story's score is the highest item signal plus a small bonus for each additional independent source.
5a. **Write (Haiku):** each new story, and each story whose lead item changed, gets a summary (≤ 3 sentences) and, if enabled in settings, a one-sentence why-it-matters, written from its best one or two items. Requests are batched about 10 stories at a time, with a fixed cached system prompt and structured output.
6. **Briefing:** once a day at the briefing time (default 07:00 Europe/London), the top stories of the last 24 hours (about 15 at most) go to the LLM, which writes a briefing of about 600 words. It has sections by category, and every claim links to its story.

Runs never overlap; a lock stops a second run from starting while one is still going. Each run is recorded with its counts and cost.

### Schedule (owner request)

- **Update frequency** is a setting: 1, 2, 4, 6, 12 or 24 runs a day. The default is **4** (00:00, 06:00, 12:00 and 18:00 Europe/London).
- The Settings page shows an **estimated monthly cost** next to each option, based on the last 7 days' average items per run and actual cost per item. Until that history exists, it uses the defaults from this spec.
- **Daily review cap:** the maximum number of items reviewed per day (default 500). This and the monthly budget are the main cost controls.

## 5. Budget and model

- `config/pricing.yaml` maps each model ID to its input and output price per million tokens. As of 2026-10-14: Haiku 5.5 $0.10 / $0.50; Sonnet 5.5 $2.00 / $10.00; Jev 1.13 $0.042 / $0 (only if the optional Jev judge is enabled).
- Every AI call records its token usage, the model and the computed cost in a `spend` table. One cap covers every provider.
- **Hard monthly cap** (default $5.00, a calendar month in Europe/London): before every call, the worst-case cost of that call (its input plus `max_tokens` of output) is checked against what's left. If it doesn't fit, the call is skipped. Collection carries on; unreviewed items are ranked by heuristic score only, and the UI shows a "budget reached" banner.
- **Models** are settings: the judge, writer and briefing models, all defaulting to `claude-haiku-5-5`. Any Claude model in `pricing.yaml` can be chosen, and Jev can be chosen for the judge.
- **Estimate**, from bake-off actuals of about $0.0001 per item reviewed:
  - Review: 500 items a day, about $0.053/day.
  - Writing: about 40 stories a day, about $0.011/day.
  - Briefing: about $0.005/day.
  - Total: about **$2.10/month**, under the $5 cap.

## 6. Feedback

- Thumbs up or down on a story is stored on the story and credited to each of its sources.
- A source's weight is `clamp(1 + 0.1 × (ups − downs over 30 days), 0.3, 2.0)` and feeds the pre-filter.
- Taste is learned in code, not in prompts. A small per-owner model, at first logistic regression over the stored judge outputs (signal, junk, category) and source trust, is refit nightly once there are at least 30 thumbs. It adjusts the ranking. Until then the judge's signal and the source weights apply.
- "Mute source" and "never show stories like this" (adds a blocklist keyword) are one click away.

## 7. Web UI

The design direction is **editorial and calm**, like a well-made morning paper:
- serif display type for headlines with a clean sans for body text;
- generous whitespace and a restrained palette with one accent colour;
- light and dark themes that follow the system;
- mobile-first, with no layout shift and no infinite scroll.

The frontend-design skill guides the visual work during implementation.

| Page | Content |
|---|---|
| Today | Story cards grouped by category, or "Top" by score. Each card shows the headline, summary, why it matters, a signal badge, source chips (lab / person / X / HN), time, thumbs, and a view expanded to every source link |
| Briefing | Today's briefing as a long-form read, plus an archive by date |
| Sources | List grouped by kind, showing trust level, weight, last success, last error and item counts. Add, edit, mute and delete |
| Settings | Update frequency (with cost estimates), daily review cap, monthly budget, judge / writer / briefing models, **API keys**, **"why it matters" on/off**, show threshold, briefing time, "Refresh now", and the spend meter for this month with a per-day chart |

**Settings details (owner request, 2026-10-14):**
- **"Why it matters" toggle** (default on). When it's off, the writer asks for the summary only, which saves output tokens. The Today page hides the line, and the cost estimates update to match. Stories already written keep their stored line, and it reappears if the toggle is turned back on.
- **Model pickers** for judge, writer and briefing, filled from `pricing.yaml`, each showing its price.
- **API keys** for Anthropic and research-engine, plus TypeSafe only if the Jev judge is enabled:
  - **Write-only.** The page shows only "set" or "not set" and when the key was last changed. A saved key is never sent back to the browser, logged or included in errors.
  - **Saving** first runs a cheap test call: a Claude `count_tokens` call, a research-engine `/health` with the key, or a one-question Jev request. A key that fails isn't saved, and the provider's error is shown with the key stripped out.
  - **Storage:** encrypted at rest in the `settings` table with Fernet. The encryption key is derived from `SECRETS_KEY` in `.env`.
  - **Priority:** a key entered in the UI wins over the `.env` value. "Clear" falls back to `.env`.
  - **Access:** changing keys or models requires the owner session. A CSRF token is needed on every settings form.
| Login | Password form |

- **Auth:** one owner password, stored as an argon2 hash in `.env` (`OWNER_PASSWORD_HASH`, made by a `make set-password` helper). The session cookie is signed with `SESSION_SECRET` and is `Secure`, `HttpOnly` and `SameSite=Lax`. Every page except `/login` and `/health` needs a session.
- **Untrusted content:** all fetched titles, snippets and LLM output are escaped by Jinja autoescape. LLM text is shown as plain text with paragraph breaks only, never as raw HTML. Outbound links get `rel="noopener noreferrer"`.

## 8. Errors

- Each source adapter catches its own errors and returns them as a `SourceResult`; one bad feed never fails a run.
- If research-engine is unreachable or returns `retryable` errors, the `x_person` and `search` sources skip that run with a recorded reason. Article fetches fall back to the snippet.
- Jev and Claude calls rely on their SDKs' retries (429/5xx, `retry-after` honoured). After that the items go back in the queue. A Claude refusal or invalid structured output leaves the story unsummarised; it shows the lead item's own snippet and gets one more try next run. A review failure marks the item `review_failed`; it gets one more try next run, then is ranked by heuristic only. An item with no verdict is never hidden by default. (In the bake-off, TypeSafe returned one `499` and Anthropic none, so both judges must tolerate per-item failures.)
- `/health` returns 200 when the database is reachable and the scheduler is alive. It reports the last run's status, but doesn't fail on it.

## 9. Data model (SQLite)

- `sources(id, kind, name, config_json, trust, enabled, weight, last_ok_at, last_error, created_at)`
- `items(id, source_id, url, canonical_url, title, author, published_at, fetched_at, snippet, body_excerpt, heuristic_score, status[new|dropped|queued|reviewed|review_failed|expired], judge_json, signal, category, story_id)`
- `stories(id, headline, category, score, summary, why_it_matters, first_seen_at, last_updated_at, feedback[-1|0|1])`
- `briefings(id, date, model, body, story_ids_json, created_at)`
- `runs(id, started_at, finished_at, trigger, counts_json, cost_usd, error)`
- `spend(id, at, model, provider[typesafe|anthropic], purpose[review|cluster|write|briefing], input_tokens, output_tokens, cache_read_tokens, cache_write_tokens, cost_usd)`
- `settings(key, value_json)`

Migrations are plain numbered SQL files applied on start-up.

## 10. Testing

- **TDD throughout.** Unit tests use fakes for `Judge`, `Writer`, `ResearchEngine`, `Clock` and HTTP (respx). Source parsers are tested against recorded fixtures (real feeds and a real research-engine search response), scrubbed of lab data.
- **Budget tests** prove the cap is never exceeded, including the worst-case pre-check.
- **Pipeline tests** cover dedupe, the X handle filter (repost accounts dropped), clustering and queue carry-over.
- **Web tests** use the FastAPI test client: auth is required, escaping works, and htmx endpoints behave.
- `tests/test_compose_policy.py` is modelled on research-engine's. It covers pinned tags, no ports, no `container_name`, healthchecks, limits, logging, hardening and the network rules.
- An optional live smoke test (marked `integration`, not run by default) makes one real Haiku call and one real research-engine search (plus one Jev call if `TYPESAFE_API_KEY` is set).
- `make test` runs ruff, ruff format check, pyright and pytest.

## 11. Deployment and ops

- **Compose project `ai-newsdesk`:** one service `app` with a pinned image built locally (tag `ai-newsdesk-app:${GIT_SHA}`), running as the non-root user 10001. It has `read_only: true` with a `/tmp` tmpfs, `cap_drop: [ALL]`, `no-new-privileges`, a healthcheck, json-file logging with rotation, and memory and CPU limits (512 MB and 0.5 CPU by default).
- **Networks:** `internal`, plus the external `proxy` with the alias `ai-newsdesk-app`. There are no ports.
- **Caddy:** `sites/ai-newsdesk.caddy` with `{$AI_NEWSDESK_HOST}`, `tls internal`, the `remote_ip {$LAB_SUBNET}` gate, `reverse_proxy ai-newsdesk-app:8000`, and `respond 403` otherwise. `AI_NEWSDESK_HOST=ai-newsdesk.toolbox.home.arpa` is appended to `/opt/caddy/.env`. The index-page link is added through research-engine's `deploy/caddy/` PR flow.
- **Make targets** in research-engine's style: `test`, `deploy` (build at the git SHA, then `up -d --wait` from `.deploy/current`), `health`, `logs`, `backup` (SQLite online backup to `backups/`), `set-password`.
- **Docs:** `CLAUDE.md`, `README.md` (quick start plus a configuration table for every `.env.example` key), `docs/OPERATIONS.md`, ADRs in `docs/adr/`, and a git-ignored `HANDOFF.local.md`.

### `.env` keys

`SECRETS_KEY`, `SESSION_SECRET`, `ANTHROPIC_API_KEY`, `RESEARCH_ENGINE_API_KEY`, `TYPESAFE_API_KEY` (optional; the API keys are fallbacks, and the Settings page can set them), `OWNER_PASSWORD_HASH`, `SITE_HOST`, `TZ` (default `Europe/London`), `LOG_LEVEL`, `APP_MEM_LIMIT` and `APP_CPUS`. Run-time tunables (frequency, caps, models, thresholds) live in the settings table, not in `.env`.

## 12. Step 0: reviewer bake-off (done, 2026-10-14; see ADR-0001)

- **Method:** throwaway scripts collected real items from the seed sources and wider ones (feeds, X via research-engine including deliberately noisy searches, HN and topic searches), filled thin items with research-engine article excerpts, and had both judges score identical input. Labels (junk / fine / important) were written by hand before any judge ran.
- **Rounds:**
  1. 55 items. Headline-only judging and the first Jev question set made Jev hide almost everything. The causes were missing article text and an over-broad "low value" question.
  2. The same 55 items with full text and revised questions: Jev was level with Haiku.
  3. A 57-item hold-out: Haiku was better.
  4. A 623-item batch, at the owner's request.
- **623-item result** (best threshold for each):

  | Judge | Junk caught | Important hidden | Fine hidden | Cost |
  |---|---|---|---|---|
  | Haiku | 280/365 | 1/30 | 34/228 | $0.066 |
  | Jev (best questions) | 234/365 | 2/30 | 49/228 | $0.032 |

- **Decision** (owner, 2026-10-14): Haiku judges in V1. Jev stays an optional `Judge`.
- **Build lessons:**
  - Always judge on article text, not headlines.
  - Fetch through research-engine gently (≤ 3 concurrent) and retry 429 and non-JSON replies with backoff.
  - Tolerate per-item AI failures.

## 13. Open risks

- **X coverage depends on the search engine's index freshness.** Posts may appear hours late, or not at all. That's accepted; the Sources page shows per-handle hit counts so dead handles are visible.
- **Clustering quality** comes from heuristics plus the LLM, with no embeddings. If duplicates slip through in practice, V1.1 can add a small embedding step.
- **Feed URLs change** and some labs have no RSS. In those cases the adapter falls back to a research-engine `search` source scoped to the lab's domain.
